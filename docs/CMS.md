# 工厂内容后台使用指南

通过 Pages CMS，可以在浏览器里维护产品、分类、网站联系方式和问答，不需要修改代码。后台修改会保存到 GitHub 仓库，再由网站构建流程检查和发布。

网站提供中英双语：英文在根路径，中文在 `/zh/`。两种语言读取同一份后台资料，分类和产品的网址片段保持相同。

## 1. 首次登录和连接仓库

1. 打开 [Pages CMS 后台](https://app.pagescms.org/)，使用有此仓库访问权限的 GitHub 账号登录。
2. 按页面提示安装 Pages CMS 的 GitHub App。选择拥有仓库的账号，并授权访问 `pengshang01-cyber/dulizhan`。
3. 打开 `dulizhan` 仓库，选择 `main` 分支。新增后台字段需要先合并对应阶段 PR，才能在 `main` 上使用。
4. 左侧应出现“产品”“分类”“网站设置”“常见问题”“定制服务内容”“团队”“案例”“资讯文章”。本仓库已经提供 `.pages.yml`，不需要重新创建或覆盖它。
5. 如果看不到仓库，请让仓库管理员检查账号权限和 App 的仓库授权范围。

登录和授权需要由实际账号持有人完成。本次开发只提供配置，未代替工厂人员登录或安装 App。官方流程见 [Pages CMS 快速开始](https://pagescms.org/docs/quick-start/)。

## 2. 中英文应该怎样填

- 每个文字内容分为“英文”和“中文”两个子字段。必填内容的英文不能为空；未确认的资料先保留 `TODO_` 开头的占位文字。
- 中文可以先留空（博客正文例外，见“如何发布文章”）。中文页面中，空白内容会自动显示对应英文；英文网站始终显示英文。产品中文名称、简介和参数说明可以逐步补充。
- 可选的角标、搜索标题、搜索简介，以及产品的定制选项详情、包装详情、适用场景，可以整组留空。只要填写其中一种语言，就必须同时填写英文。
- 型号、网址片段、图片、尺寸、克重和数字不用翻译，也不用保存两遍。起订量如果只是一个数字，填在英文栏一次，中文栏留空即可共用。
- 工厂已确认的花色多、食品级材质、工厂直供批发价和支持定制，可以直接写成肯定表述。MOQ、交期、证书、产能、客户名称等具体资料必须先向工厂确认，不要自行补数字或证书名称。
- 对外说明使用第一人称 `we`。不要把未经确认的“免费打样”等承诺写进内容。

## 3. 新增或修改分类

1. 打开“分类”，选择新建。
2. 填分类名称和一句简短简介，英文必填，中文选填。
3. 上传或选择分类封面。还没有实拍时，继续使用带 `Placeholder` 标记的占位图。
4. 填“排序”，使用整数，越小越靠前。需要放在首页的分类勾选“显示在首页”。
5. **检查新建时的文件名**：只使用小写英文字母、数字和连字符，例如 `tulip-shaped-baking-cups.json`。不要使用中文、空格或斜杠，不要重复已有文件名。界面如果已经显示 `.json`，不要再补第二遍。
6. 保存分类，再去“产品”里给产品选择这个分类。

分类文件名去掉 `.json` 后就是分类的网址片段。例如上面的文件对应 `/products/tulip-shaped-baking-cups/`。分类名称可以修改；文件名不要随意修改。删除或改名分类前，必须先把其中的产品移到其他分类，否则构建会提示分类不存在。

后台使用动态分类选择器，新增分类保存后会出现在产品分类下拉框，不需要维护另一张固定分类名单。该功能使用官方的 [Reference 字段](https://pagescms.org/docs/configuration/fields/reference/)；文件命名遵循官方的 [Filename 配置](https://pagescms.org/docs/configuration/content/filename/)。

**为什么保存分类后网站没有显示？** 没有产品的分类会自动隐藏：首页、产品中心筛选和页脚都不会显示，也不会生成该分类页。先给分类添加至少一个有效产品。首页还要求勾选“显示在首页”，并按排序最多展示六个分类；符合条件的分类超过六个时，会出现 `View all categories` 入口。

## 4. 新增产品

1. 打开“产品”，选择新建。
2. 填“产品网址片段”，例如 `tulip-cup-example`，只用小写英文、数字和连字符。文件名会自动使用此值并加 `.json`。同一个网址片段只能用于一个产品，保存后不要随意更改。
3. 填型号、产品名称和简介，并从“所属分类”下拉框选择已保存的分类。产品没有确认的通用型号时使用独立的 `TODO_SKU_` 占位。每个尺寸有型号时填入该行的“规格名称”，例如 `5039`。
4. 添加至少一张产品图片，第一张是产品卡片封面。可添加多张；不使用网络抓取图或 AI 生成图冒充实拍。
5. 填材质、克重和至少一组尺寸。克重可填 `110`、`260–300` 或 `24 / 31 / 40`，网站统一加单位。圆形用底径、口径和高度栏，只填毫米数值。方形、长方形、纸片等可留空直径栏，在“规格说明”填实际尺寸，例如 `Base 65×65 mm, top 85×85 mm, height 35 mm`，中文填“底部 65×65 mm，顶部 85×85 mm，高度 35 mm”。
6. 在“颜色”“图案”“产品问答”中按需新增列表项。每项可分别填英文和中文；这些列表允许为空。不用的空行请直接删除，不要保留未填写英文的列表项，否则构建会提示必填内容缺失。
7. 选择是否支持定制，未确认时选“待工厂确认”。产品起订量和交期可留空，页面会用“网站设置”里的说明。装箱、外箱、起订量或交期仅针对某一规格时，在“包装详情”中注明对应规格。
8. 按需填写定制选项详情、包装详情和适用场景。这些是普通多行文字，不需要写 Markdown 或代码；整组留空会隐藏对应区块。
9. 角标只有在工厂确认后才填写，不要随意标记 `Best Seller`。搜索标题和搜索简介可以留空，网站会使用产品名称和简介。
10. 填整数排序，检查后保存。等构建通过，再在产品中心、分类页和产品详情页查看。

保存时若提示必填字段缺失，先完成该字段；没有资料时用明确的 `TODO_` 占位，不要编造。复制旧产品时，务必先改成新的网址片段和型号。

M9 的实拍待补项见 [产品图片清单](import/images-needed.md)，可按网址片段找到对应产品和工厂电脑的店铺图片目录。

维护同事可从 `data-import/junbeili-products.xlsx` 重做本批导入。运行 `npm run import:products -- --plan` 先查看逐行合并方案，再运行 `npm run import:products` 写入分类和产品。再次导入会覆盖本批相同网址片段的 CMS 编辑，请先核对差异。工作簿备注供内部核对，公开规格只从备注提取尺寸。

## 5. 上传图片

各编辑字段会打开对应媒体目录，请从字段里的上传或选择按钮进入：

| 用途                         | 后台上传目录                    | 建议图片尺寸                                                    |
| ---------------------------- | ------------------------------- | --------------------------------------------------------------- |
| 产品图片                     | `src/assets/images/products/`   | 正方形，约 1200 × 1200 像素，留出产品四周空白                   |
| 文章封面与正文图             | `src/assets/images/blog/`       | 封面建议 1600 × 900；正文图长边约 1200–1600，保持原比例           |
| 分类封面                     | `src/assets/images/categories/` | 约 1200 × 900 像素，主体保持居中                                |
| 证书、微信二维码、团队、案例 | `src/assets/images/site/`       | 证书保留可读文字；二维码建议至少 600 × 600 像素，并保留边缘留白 |

这些尺寸是上传建议，不是产品参数。使用 JPG、PNG、WebP 或 AVIF；建议单张图片尽量控制在 1 MB 左右，二维码优先 PNG。上传前用英文文件名，例如 `tulip-cup-front.webp`，避免中文、空格和特殊符号。后台会清理文件名，但仍建议上传前起好名字。不要删除仍被产品、分类或网站资料引用的图片。

上传证书前确认名称和图片真实且可以公开；微信二维码上传后，用手机实际扫码核对。没有资料时图片字段留空，不要填 `TODO_IMAGE` 这样的假图片路径。

供维护人员核对：产品和分类 JSON 里的图片路径分别保存为 `../../assets/images/products/文件名`、`../../assets/images/categories/文件名`；网站、团队和案例 JSON 中保存为 `../assets/images/site/文件名`。这些是相对对应 JSON 文件的路径，不是访问网站的 URL。产品与分类图片由 Astro 的 `image()` 校验和处理。后台配置使用官方 [Media 的 input/output](https://pagescms.org/docs/configuration/media/) 和 [Image 字段](https://pagescms.org/docs/configuration/fields/image/)；路径规则参见 [Astro 内容集合图片文档](https://docs.astro.build/en/guides/images/#images-in-content-collections)。正常使用后台选择图片即可，不需要手写路径。

## 6. 网站设置和常见问题

“网站设置”可以修改公司名称、副标题、顶部公告、联系方式、地址、政策说明、首页数字、视频、证书和社交链接。顶部公告中的 `TODO_` 项不显示，手机端只展示第一条有效公告；首页数字中的 `TODO_` 仍会显示待补提示。视频编号未填时隐藏视频区块，证书缺真实名称或图片时不展示卡片。

微信号和微信二维码分别填写：微信号留空或为 `TODO_` 时隐藏整张微信卡片；填写真实微信号后显示卡片，二维码未上传时不显示图片。中文站优先使用微信悬浮入口，点击可看二维码和复制微信号，未设置微信时回退 WhatsApp；英文站悬浮入口仍是 WhatsApp，联系页可以显示 WeChat 卡片。WhatsApp 号码应带国家区号，未填写或为 `TODO_` 时不显示入口。

“常见问题”按下单、样品、运输与付款、定制、质量与安全五组管理。勾选“首页精选问题”的问答会同时出现在首页，因此只需修改一次。中文答案可以先留空。

部分答案含有 `{{site.stockMoq}}` 这样的文字，这是读取“网站设置”的变量，访客看到的是实际设置值。建议保留它们，只在“网站设置”更新资料，避免几个页面出现不同数字。可用变量包括：

| 变量                          | 对应网站设置 |
| ----------------------------- | ------------ |
| `{{site.stockMoq}}`           | 现货起订量   |
| `{{site.customMoq}}`          | 定制起订量   |
| `{{site.sampleLeadTime}}`     | 打样时间     |
| `{{site.productionLeadTime}}` | 生产交期     |
| `{{site.sampleCost}}`         | 样品政策     |
| `{{site.paymentTerms}}`       | 付款方式     |
| `{{site.shippingMethods}}`    | 运输方式     |
| `{{site.certificates}}`       | 证书名称     |

如果确实需要固定文字，也只能用工厂确认的说明替换整个变量。不要修改变量里的英文名称、删掉一半花括号，或把变量替换成重复的 `TODO_` 文字，否则以后改网站设置就无法同步这段答案。

“定制服务内容”维护流程步骤。“团队”和“案例”没有真实资料时保持空列表，网站会隐藏对应区块；需要展示时再添加已确认的文字和真实图片。

网站设置新增“访问统计 → GA4 衡量 ID”：填 Google Analytics 提供的 G- 开头标识；未启用统计时保留 TODO 或留空。TODO / 空值时 Cookie 横幅及设置入口也隐藏；填写有效 ID 后，只有访客接受 Cookie 才会加载统计。GA4 在中国大陆的访问数据会缺失，不能当作国内总流量。可选“网站标志”上传真实公司标志，没有时留空。

产品 SEO 标题建议英文不超过 60 字符、中文不超过 30 字符；描述建议英文不超过 155 字符、中文不超过 80 字符。留空时网站自动生成。若 CI 报同语言标题或描述重复，请给对应产品填写更明确的 SEO 文案。

## 7. 保存以后多久上线

保存到 `main` 会生成 GitHub 提交并触发本仓库的 CI 检查。通常需要等待数分钟，但时间取决于排队、图片数量和托管平台状态，不保证固定时长。

本站使用 Cloudflare Workers 静态资源部署，正式站为 [junbeili.com](https://junbeili.com)。Workers Builds 在 CMS 保存到 GitHub 的 `main` 分支后构建和部署。等待该次部署成功再刷新正式站核对内容。 [workers.dev 测试地址](https://dulizhan.pengshang01.workers.dev)

每次保存都先查看 GitHub 检查是否通过，再查看 Cloudflare Worker 的 Builds 部署状态。两处成功后再打开实际网站，必要时刷新浏览器。联系页和产品详情页已接入询盘表单；实际发信还需要管理员按 README 配置 Turnstile 和 Resend，CMS 不保存这些密钥。

补齐资料后，由工厂在“网站设置”开启“允许搜索引擎收录”。新部署会同步更新 robots.txt、sitemap、页面 meta 和静态响应头。关闭时仍可直接打开网站链接，站点继续向爬虫发送不抓取、不收录的指令。 [正式开放操作](LAUNCH.md)

## 8. 填错了怎么办

1. 在 [GitHub 仓库的 Actions 页面](https://github.com/pengshang01-cyber/dulizhan/actions) 找到最新一次检查。绿色表示通过，红色表示失败；确认它对应自己的保存时间和提交。
2. 点进失败记录，展开红色步骤。常见提示包括英文必填、图片不存在、尺寸不是正数、分类文件不存在。记录报错里的产品文件名和字段名。
3. 回到 Pages CMS 打开相应条目，修正后再次保存。新保存会重新运行检查，不需要在 GitHub 里修改代码。
4. 如果刚改过分类文件名，先恢复原名称，或把所有相关产品改选到已有分类。缺失图片可以重新上传并重新选择。
5. 不清楚错误时，把 Actions 记录链接、保存时间和相关产品名称发给维护人员。误删内容需要恢复时，请维护人员从 GitHub 提交历史恢复，不要反复创建同名条目尝试覆盖。

如果 CI 已通过但公开网站没有更新，请让管理员检查 Cloudflare Workers Builds 的仓库连接、构建和部署记录。CI 和部署失败都会保留各自的错误信息；保存失败或尚未部署时，不要把后台预览当作已上线结果。

## 9. 后台文件说明

分类和产品各自一条记录对应一个 JSON 文件，便于新增和检查。网站设置也是 JSON；常见问题、定制步骤、团队和案例分别使用一个 JSON 列表文件。编辑人员只需操作后台表单，列表可逐项增删，不需要打开 JSON。

这些表单由根目录 `.pages.yml` 定义，使用官方的 [Content 配置](https://pagescms.org/docs/configuration/content/)、[Object 双语字段](https://pagescms.org/docs/configuration/fields/object/) 和 [List 列表规则](https://pagescms.org/docs/configuration/content/list/)。如需要新增一种全新的字段或界面功能，请联系维护人员；新增分类、产品和已有列表内容无需改配置。

## 10. 如何发布文章

1. 打开“资讯文章”，点击新建。新建时填写文件名，例如 `choosing-baking-cups.json`，只用小写英文、数字和连字符；如果界面已带扩展名，不再重复填写。文件名决定文章网址，发布后不要随意修改。
2. 填“文章标题”和“文章简介”的英文与中文。英文必填；标题建议英文不超过 60 字符、中文不超过 30 字符，简介建议英文不超过 155 字符、中文不超过 80 字符。两篇文章不要使用相同标题或简介。
3. 填发布日期（YYYY-MM-DD），有实质修改时再填更新日期；更新日期不能早于发布日期。日期不会自动定时发布，是否公开由“草稿”开关决定。
4. 上传封面，在“标签”中按需增加双语标签。没有标签时删除空项。在“相关产品”多选框选真实产品；这些产品会在文末显示，并支持加入询价单。删除或改名已引用的产品前，要先取消或更改文章引用。
5. 用“正文（英文）”富文本编辑器写文章；“正文（中文）”可稍后补充。工具栏支持段落、列表、链接、图片和标题，选二级 / 三级标题会自动加入目录。文章大标题由标题字段生成，不需要在正文再写一遍一级标题。需要表格时，可切到 Markdown 模式编辑。
6. 正文图片使用编辑器的图片按钮，选择“资讯文章图片”媒体库；不要粘贴远程图片网址，也不要粘贴带脚本、表单或视频 iframe 的网页源码。正文图片会经 Astro 优化，带宽高并懒加载。维护人员核对路径时，封面及 Markdown 图片路径都是 `../../assets/images/blog/英文文件名.webp`。
7. **新文章默认是草稿。** 保存草稿不会在网站、列表或 sitemap 中公开；后台可以继续修改。发布前核实正文、真实图片、产品链接及所有 [TODO]，然后关闭“草稿”并保存。还没准备好时不要为了看线上效果而关闭草稿。
8. 构建和部署成功后，英文文章出现在 `/blog/`，每页九篇。只有填写了非空中文正文，才生成 `/zh/blog/文章文件名/` 并进入中文列表；不会把整篇英文正文放到中文站。两种正文都有时才显示文章语言切换和对应的搜索引擎语言链接。中文标题、简介和标签仍可留空回退英文。
9. 暂时撤下文章：重新勾选“草稿”并保存。没有公开文章时，网站显示正式空状态与产品、询价入口。仓库自带的两篇示例是写作提纲，必须核对 [TODO] 并替换占位图后才能发布。

Pages CMS 使用官方 [Rich-text Markdown 编辑器](https://pagescms.org/docs/configuration/fields/rich-text/) 和 [Reference 多选](https://pagescms.org/docs/configuration/fields/reference/)。文章保存为一个 JSON 文件，两份正文分别为 `bodyEn` / `bodyZh`；编辑人员无需手写 JSON。后台没有正式站的即时预览，保存后请以 GitHub 检查和 Workers 构建结果为准。

准备上线资料时查看 [上线清单](LAUNCH-CHECKLIST.md)。维护人员可运行 `npm run todo:report` 更新待补内容，人工维护的上线检查勾选不会被覆盖。


## 11. 如何更换首页主图、车间照片、Logo

统一打开 **“网站设置”**，不需要找单独的页面配置或修改代码。该入口同时管理联系方式与页面图片，更容易查找。

| 后台字段 | 填写与建议尺寸 | 留空后的显示 |
| --- | --- | --- |
| 网站 Logo | 真实标志；建议透明 PNG，至少 512 × 512；避免四周大面积留白 | 原有图标与公司文字；搜索引擎资料不输出 logo |
| 默认分享图 | 1200 × 630；主要内容放在画面中间，四周留出裁切空间 | 现有 Placeholder 分享图 |
| 首页主图 | 真实主打产品或产品组合，建议 1600 × 1200（4:3） | 现有首页 Placeholder |
| 首页主图说明 | 简短描述画面；填写英文，中文选填；中文空时显示英文 | 有上传图时使用品类通用说明；无图时保留占位说明 |
| 关于我们车间与设备照片 | 每项上传一张图片并填写说明，建议 1600 × 1067（3:2） | 列表为空时恢复四张原有占位图 |
| 工厂视频封面 | 可选，1280 × 720；先配置有效 YouTube 视频 ID | 沿用该视频的缩略图；没有视频 ID 时整个视频区不显示 |

操作步骤：

1. 选择相应图片字段，上传到 **“网站资料图片”**，或选择已上传图片；支持 JPG、JPEG、PNG、WebP、AVIF。用小写英文、数字和连字符命名，例如 hero-products.jpg；不要使用客户未授权图片或 AI 产品图代替实拍。
2. 首页主图上传后填写“首页主图说明”。车间图库点新增，上传图片、填写英文说明及可选中文说明；拖动条目调整顺序，删除不需要的条目。每条图库记录必须同时有图片和英文说明。
3. 图片说明应描述实际画面，如印刷车间、成型设备。它同时帮助读屏用户理解图片；车间图说明也显示在图片下方。不要用未核实的产能、设备数量或证书作为说明。
4. 保存后等待 GitHub 检查和 Workers 部署成功，再打开中英文首页和关于页检查；手机也看一遍。网站会自动生成适合屏幕的 WebP、宽高和加载设置，不需要自行压缩成多份文件。
5. 更换图片时直接重新选择并保存。想恢复默认，清空对应图片字段；车间图库需删除全部条目。删除媒体文件前，确认没有产品、文章或其他条目仍引用它。

默认分享图用于没有专属分享图的页面；文章配置非占位封面时优先使用该封面，产品页沿用全站默认分享图。Logo 同时用于页头和搜索引擎的 Organization.logo，只有上传后才输出。社交平台可能缓存旧分享图，部署后需要等待平台重新抓取。

其他图片入口：产品 → 产品图片；分类 → 分类封面；资讯文章 → 文章封面 / 正文图片；网站设置 → 微信二维码 / 证书；团队 → 图片；案例 → 图片。定制页展示“案例”图片，联系页展示“微信二维码”，无需另建重复字段。界面按钮中的 SVG 图标属于设计组件，不是工厂素材。

维护人员核对路径：上传文件实际位于 src/assets/images/site/，CMS 写入 ../assets/images/site/文件名.png；双语数据的路径共用一份。该相对路径由网站在构建时解析为 Astro 图片，不要自行改成远程网址。参考 [Pages CMS 媒体配置](https://pagescms.org/docs/configuration/media/) 与 [图片字段](https://pagescms.org/docs/configuration/fields/image/)。
