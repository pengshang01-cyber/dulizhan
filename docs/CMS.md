# 工厂内容后台使用指南

通过 Pages CMS，可以在浏览器里维护产品、分类、网站联系方式和问答，不需要修改代码。后台修改会保存到 GitHub 仓库，再由网站构建流程检查和发布。

网站提供中英双语：英文在根路径，中文在 `/zh/`。两种语言读取同一份后台资料，分类和产品的网址片段保持相同。

## 1. 首次登录和连接仓库

1. 打开 [Pages CMS 后台](https://app.pagescms.org/)，使用有此仓库访问权限的 GitHub 账号登录。
2. 按页面提示安装 Pages CMS 的 GitHub App。选择拥有仓库的账号，并授权访问 `pengshang01-cyber/dulizhan`。
3. 打开 `dulizhan` 仓库，选择 `main` 分支。新增后台字段需要先合并对应阶段 PR，才能在 `main` 上使用。
4. 左侧应出现“产品”“分类”“网站设置”“常见问题”“定制服务内容”“团队”“案例”。本仓库已经提供 `.pages.yml`，不需要重新创建或覆盖它。
5. 如果看不到仓库，请让仓库管理员检查账号权限和 App 的仓库授权范围。

登录和授权需要由实际账号持有人完成。本次开发只提供配置，未代替工厂人员登录或安装 App。官方流程见 [Pages CMS 快速开始](https://pagescms.org/docs/quick-start/)。

## 2. 中英文应该怎样填

- 每个文字内容分为“英文”和“中文”两个子字段。必填内容的英文不能为空；未确认的资料先保留 `TODO_` 开头的占位文字。
- 中文可以先留空。中文页面中，空白内容会自动显示对应英文；英文网站始终显示英文。产品中文名称、简介和参数说明可以逐步补充。
- 可选的角标、搜索标题、搜索简介，以及产品的定制选项详情、包装详情、适用场景，可以整组留空。只要填写其中一种语言，就必须同时填写英文。
- 型号、网址片段、图片、尺寸、克重和数字不用翻译，也不用保存两遍。起订量如果只是一个数字，填在英文栏一次，中文栏留空即可共用。
- 工厂已确认的花色多、食品级材质、工厂直供批发价和支持定制，可以直接写成肯定表述。MOQ、交期、证书、产能、客户名称等具体资料必须先向工厂确认，不要自行补数字或证书名称。
- 对外说明使用第一人称 `we`。不要把未经确认的“免费打样”等承诺写进内容。

## 3. 新增或修改分类

1. 打开“分类”，选择新建。
2. 填分类名称和一句简短简介，英文必填，中文选填。
3. 上传或选择分类封面。还没有实拍时，继续使用带 `Placeholder` 标记的占位图。
4. 填“排序”，使用整数，越小越靠前。需要放在首页的分类勾选“显示在首页”。
5. **检查新建时的文件名**：只使用小写英文字母、数字和连字符，例如 `tulip-baking-cups.json`。不要使用中文、空格或斜杠，不要重复已有文件名。界面如果已经显示 `.json`，不要再补第二遍。
6. 保存分类，再去“产品”里给产品选择这个分类。

分类文件名去掉 `.json` 后就是分类的网址片段。例如上面的文件对应 `/products/tulip-baking-cups/`。分类名称可以修改；文件名不要随意修改。删除或改名分类前，必须先把其中的产品移到其他分类，否则构建会提示分类不存在。

后台使用动态分类选择器，新增分类保存后会出现在产品分类下拉框，不需要维护另一张固定分类名单。该功能使用官方的 [Reference 字段](https://pagescms.org/docs/configuration/fields/reference/)；文件命名遵循官方的 [Filename 配置](https://pagescms.org/docs/configuration/content/filename/)。

预置分类如下，可以继续补充产品：

| 分类文件名中的网址片段       | 中文名称       |
| ---------------------------- | -------------- |
| `standard-cupcake-liners`    | 普通蛋糕纸托   |
| `greaseproof-cupcake-liners` | 防油纸托       |
| `foil-baking-cups`           | 铝箔杯         |
| `tulip-baking-cups`          | 郁金香杯       |
| `lotus-baking-cups`          | 荷花杯         |
| `muffin-cups`                | 马芬杯         |
| `rolled-rim-baking-cups`     | 卷边硬质烤杯   |
| `basque-cheesecake-liners`   | 巴斯克蛋糕纸   |
| `paper-baking-molds`         | 纸质烤模       |
| `kraft-trays-boxes`          | 牛皮纸托盘与盒 |
| `dessert-cups`               | 甜品杯         |
| `specialty-packaging`        | 特殊包装       |

**为什么保存分类后网站没有显示？** 没有产品的分类会自动隐藏：首页、产品中心筛选和页脚都不会显示，也不会生成该分类页。先给分类添加至少一个有效产品。首页还要求勾选“显示在首页”，并按排序最多展示六个分类；符合条件的分类超过六个时，会出现 `View all categories` 入口。

## 4. 新增产品

1. 打开“产品”，选择新建。
2. 填“产品网址片段”，例如 `tulip-cup-example`，只用小写英文、数字和连字符。文件名会自动使用此值并加 `.json`。同一个网址片段只能用于一个产品，保存后不要随意更改。
3. 填型号、产品名称和简介，并从“所属分类”下拉框选择已保存的分类。未知的示例型号使用 `TODO-001` 这样明显的占位形式。
4. 添加至少一张产品图片，第一张是产品卡片封面。可添加多张；不使用网络抓取图或 AI 生成图冒充实拍。
5. 填材质、克重和至少一组尺寸。尺寸栏只输入大于零的数字，不写 `mm`，不加千分位逗号；克重也只填数字。尚未确认时使用 `TODO_` 占位。顶部直径可留空。
6. 在“颜色”“图案”“产品问答”中按需新增列表项。每项可分别填英文和中文；这些列表允许为空。不用的空行请直接删除，不要保留未填写英文的列表项，否则构建会提示必填内容缺失。
7. 选择是否支持定制，填写起订量、包装方式、外箱规格和交期。未确认的资料继续用 `TODO_` 占位。
8. 按需填写定制选项详情、包装详情和适用场景。这些是普通多行文字，不需要写 Markdown 或代码；整组留空会隐藏对应区块。
9. 角标只有在工厂确认后才填写，不要随意标记 `Best Seller`。搜索标题和搜索简介可以留空，网站会使用产品名称和简介。
10. 填整数排序，检查后保存。等构建通过，再在产品中心、分类页和产品详情页查看。

保存时若提示必填字段缺失，先完成该字段；没有资料时用明确的 `TODO_` 占位，不要编造。复制旧产品时，务必先改成新的网址片段和型号。

## 5. 上传图片

各编辑字段会打开对应媒体目录，请从字段里的上传或选择按钮进入：

| 用途                         | 后台上传目录                    | 建议图片尺寸                                                    |
| ---------------------------- | ------------------------------- | --------------------------------------------------------------- |
| 产品图片                     | `src/assets/images/products/`   | 正方形，约 1200 × 1200 像素，留出产品四周空白                   |
| 分类封面                     | `src/assets/images/categories/` | 约 1200 × 900 像素，主体保持居中                                |
| 证书、微信二维码、团队、案例 | `src/assets/images/site/`       | 证书保留可读文字；二维码建议至少 600 × 600 像素，并保留边缘留白 |

这些尺寸是上传建议，不是产品参数。使用 JPG、PNG、WebP 或 AVIF；建议单张图片尽量控制在 1 MB 左右，二维码优先 PNG。上传前用英文文件名，例如 `tulip-cup-front.webp`，避免中文、空格和特殊符号。后台会清理文件名，但仍建议上传前起好名字。不要删除仍被产品、分类或网站资料引用的图片。

上传证书前确认名称和图片真实且可以公开；微信二维码上传后，用手机实际扫码核对。没有资料时图片字段留空，不要填 `TODO_IMAGE` 这样的假图片路径。

供维护人员核对：产品和分类 JSON 里的图片路径分别保存为 `../../assets/images/products/文件名`、`../../assets/images/categories/文件名`；网站、团队和案例 JSON 中保存为 `../assets/images/site/文件名`。这些是相对对应 JSON 文件的路径，不是访问网站的 URL。产品与分类图片由 Astro 的 `image()` 校验和处理。后台配置使用官方 [Media 的 input/output](https://pagescms.org/docs/configuration/media/) 和 [Image 字段](https://pagescms.org/docs/configuration/fields/image/)；路径规则参见 [Astro 内容集合图片文档](https://docs.astro.build/en/guides/images/#images-in-content-collections)。正常使用后台选择图片即可，不需要手写路径。

## 6. 网站设置和常见问题

“网站设置”可以修改公司名称、副标题、顶部公告、联系方式、地址、政策说明、首页数字、视频、证书和社交链接。顶部公告中的 `TODO_` 项不显示，手机端只展示第一条有效公告；首页数字中的 `TODO_` 仍会显示待补提示。视频编号未填时隐藏视频区块，证书缺真实名称或图片时不展示卡片。

微信号和微信二维码分别填写：微信号留空或为 `TODO_` 时隐藏整张微信卡片；填写真实微信号后显示卡片，二维码未上传时不显示图片。中文站优先使用微信悬浮入口，点击可看二维码和复制微信号，未设置微信时回退 WhatsApp；英文站悬浮入口仍是 WhatsApp，联系页可以显示 WeChat 卡片。WhatsApp 号码应带国家区号，未填写或为 `TODO_` 时不显示入口。

“常见问题”按下单、样品、运输与付款、定制、质量与安全五组管理。勾选“首页精选问题”的问答会同时出现在首页，因此只需修改一次。中文答案可以先留空。

部分答案含有 `{{site.stockMoq}}` 这样的文字，这是读取“网站设置”的变量，访客看到的是实际设置值。建议保留它们，只在“网站设置”更新资料，避免几个页面出现不同数字。可用变量包括：

| 变量                          | 对应网站设置 |
| ----------------------------- | ------------ |
| `{{site.stockMoq}}`           | 现货起订量   |
| `{{site.customMoq}}`          | 定制起订量   |
| `{{site.sampleLeadTime}}`     | 打样时间     |
| `{{site.productionLeadTime}}` | 生产交期     |
| `{{site.sampleCost}}`         | 样品政策     |
| `{{site.paymentTerms}}`       | 付款方式     |
| `{{site.shippingMethods}}`    | 运输方式     |
| `{{site.certificates}}`       | 证书名称     |

如果确实需要固定文字，也只能用工厂确认的说明替换整个变量。不要修改变量里的英文名称、删掉一半花括号，或把变量替换成重复的 `TODO_` 文字，否则以后改网站设置就无法同步这段答案。

“定制服务内容”维护流程步骤。“团队”和“案例”没有真实资料时保持空列表，网站会隐藏对应区块；需要展示时再添加已确认的文字和真实图片。

## 7. 保存以后多久上线

保存到 `main` 会生成 GitHub 提交并触发本仓库的 CI 检查。通常需要等待数分钟，但时间取决于排队、图片数量和托管平台状态，不保证固定时长。

**CMS 保存成功不等于网站已经发布。** 本仓库使用 Cloudflare Workers 静态资源部署，当前站点地址为 [dulizhan.pengshang01.workers.dev](https://dulizhan.pengshang01.workers.dev)。Workers Builds 从 GitHub 的 `main` 分支自动构建；构建命令为 `npm run build`，部署命令为 `npx wrangler deploy`。保存后仍需等待该次构建部署成功。

每次保存都先查看 GitHub 检查是否通过，再查看 Cloudflare Worker 的 Builds 部署状态。两处成功后再打开实际网站，必要时刷新浏览器。联系页表单仍等待 M5 接入，本阶段后台不会启用表单发送邮件。

“网站设置”中的“允许搜索引擎收录”在正式上线前保持关闭。M8 确认上线时再开启；保存并部署后会同时更新 robots.txt、页面 meta 和静态响应头，无需手动改文件。关闭状态的网站仍可通过链接访问，但会向搜索引擎发出不抓取、不收录的指令。

## 8. 填错了怎么办

1. 在 [GitHub 仓库的 Actions 页面](https://github.com/pengshang01-cyber/dulizhan/actions) 找到最新一次检查。绿色表示通过，红色表示失败；确认它对应自己的保存时间和提交。
2. 点进失败记录，展开红色步骤。常见提示包括英文必填、图片不存在、尺寸不是正数、分类文件不存在。记录报错里的产品文件名和字段名。
3. 回到 Pages CMS 打开相应条目，修正后再次保存。新保存会重新运行检查，不需要在 GitHub 里修改代码。
4. 如果刚改过分类文件名，先恢复原名称，或把所有相关产品改选到已有分类。缺失图片可以重新上传并重新选择。
5. 不清楚错误时，把 Actions 记录链接、保存时间和相关产品名称发给维护人员。误删内容需要恢复时，请维护人员从 GitHub 提交历史恢复，不要反复创建同名条目尝试覆盖。

如果 CI 已通过但公开网站没有更新，请让管理员检查 Cloudflare Workers Builds 的仓库连接、构建和部署记录。CI 和部署失败都会保留各自的错误信息；保存失败或尚未部署时，不要把后台预览当作已上线结果。

## 9. 后台文件说明

分类和产品各自一条记录对应一个 JSON 文件，便于新增和检查。网站设置也是 JSON；常见问题、定制步骤、团队和案例分别使用一个 JSON 列表文件。编辑人员只需操作后台表单，列表可逐项增删，不需要打开 JSON。

这些表单由根目录 `.pages.yml` 定义，使用官方的 [Content 配置](https://pagescms.org/docs/configuration/content/)、[Object 双语字段](https://pagescms.org/docs/configuration/fields/object/) 和 [List 列表规则](https://pagescms.org/docs/configuration/content/list/)。如需要新增一种全新的字段或界面功能，请联系维护人员；新增分类、产品和已有列表内容无需改配置。
