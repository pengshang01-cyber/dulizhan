## 4. 偏离与新增依赖

- 博客选 JSON，正文为独立 bodyEn / bodyZh Markdown 字符串，编辑人员使用 Pages CMS 富文本界面；不恢复旧的 Markdown 正文文件。标签使用 {en,zh} 对象列表，遵守全站访客文字双语约定。
- CMS 字段按官方文档核验：[Rich-text](https://pagescms.org/docs/configuration/fields/rich-text/)、[Reference](https://pagescms.org/docs/configuration/fields/reference/)、[Date](https://pagescms.org/docs/configuration/fields/date/)、[Filename](https://pagescms.org/docs/configuration/content/filename/)。产品多选保存 {fields.slug}；日期使用 yyyy-MM-dd，updated 默认空；新文章文件名在创建时填写。封面和正文图片路径均为 ../../assets/images/blog/文件名，与 image() / 正文优化器匹配。
- 新增直接构建依赖 `@astrojs/markdown-satteri@0.4.10`：这是当前 Astro 已在用的 Markdown 引擎，直接声明用于处理 CMS JSON 正文，不增加新的浏览器渲染框架。核验官方 withastro/astro 仓库、npm tarball integrity；安装禁用生命周期脚本，npm audit 为 0 漏洞。SHA-512：`sha512-3h/wheVjZIcP/m295nkiUjOvCsCs6QpvZ3l4BfDU4ghNQcrcFrNVu1+K+I+YT61hH9tuCDQiGdF8QDzfDoG42w==`。
- Lighthouse 13.6.0 是仓库外隔离审计工具，不加入网站依赖；核验官方 GoogleChrome/lighthouse 和 npm integrity，安装 --ignore-scripts，118 包审计 0 漏洞；复用已有浏览器，未另下载 Chrome。官方 [Node 使用说明](https://github.com/GoogleChrome/lighthouse/blob/main/docs/readme.md#using-programmatically)。未改变 Worker 配置或部署方式。
- 草稿页面、正文、标题不输出；集合 image() 导入的通用占位图片资源可能仍被 Astro 打包，但没有任何页面引用草稿文章。
- [上线清单](../LAUNCH-CHECKLIST.md) 扫描 22 个 JSON，列出 95 个待补字段、20 处占位图引用、3 个空图片位、3 个示例产品；另外明确列出首页 / 车间图。目前它们由组件直接引用，没有 CMS 字段，清单要求将真实素材交维护人员替换，不声称已有后台上传入口；本轮未扩展新的首页内容模型。
